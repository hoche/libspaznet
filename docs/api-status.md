# API status

What's stable, what's experimental, what's a stub, and what's missing
entirely. Update this table when the wiring changes.

Following the protocol-handler restructure (commits a7fab2d through
05f818f, 2026-05-31), the protocol implementations live under
`example/<protocol>/` and are linked as separate libraries
(`spaznet_http`, `spaznet_http_websocket`, `spaznet_http2`,
`spaznet_udp`, `spaznet_quic_http3`).  The core `spaznet` library
holds only the low-level server / IOContext / Socket / Task /
PlatformIO.

| Subsystem | Public type / entry point | Status | Notes |
|---|---|---|---|
| Core | `spaznet::Server` / `spaznet::ServerConfig` | **Stable** | Public API. `Server(N)` = 1 loop + N coroutine workers; `Server(ServerConfig{.loops=N})` = N independent loops with TCP accept-and-shard for reactor connections (UDP stays on loop 0). `set_connection_handler` / `set_datagram_handler` (coroutine) and `set_connection_factory` / `set_sync_datagram_handler` (reactor) are the dispatch hooks; the example libraries provide `make_dispatcher(...)` / `make_reactor_dispatcher(...)` factories. See `docs/reactor-threading.md`. |
| Core | `spaznet::Socket` | **Stable** | Move-only. `async_read` / `async_write` / `close`. When `SPAZNET_HAS_TLS`, may carry opaque TLS state from `listen_tls` (memory-BIO `TlsStream` under the same await API; `enable_serialized_io` for coroutine sharing). Not safe to share across coroutines on different threads without that serialization. |
| Core | `spaznet::TlsConfig` / `Server::listen_tls` | **Stable** | Gated on `SPAZNET_ENABLE_TLS` / `SPAZNET_HAS_TLS` (OpenSSL 1.1.1+). Per-listener ALPN (`http/1.1` or `h2`); memory-BIO `TlsStream` under Socket / BufferedConnection so HTTP/WS dispatchers stay plaintext. Reactor: no TLS mutex; coroutine: `enable_serialized_io` via `attach_tls`. Accept→factory handoff is `thread_local`. Independent of QUIC TLS. |
| Core | `spaznet::Datagram` | **Stable** | Plain struct: bytes + peer addr + raw sockaddr_storage + listen fd. Passed to `DatagramHandler` callbacks. |
| Core | `spaznet::ConnectionHandler` / `spaznet::DatagramHandler` | **Stable** | `std::function<Task(Socket)>` / `std::function<Task(Datagram)>` typedefs. |
| Core | `spaznet::IOContext` | **Stable** | Owned by `Server`; advanced users can construct one directly for unit tests. |
| Core | `spaznet::Task` | **Stable** | C++20 coroutine return type. Symmetric transfer + ref-counted control block. |
| Core | `spaznet::codec::huffman_{encode,decode}` | **Stable** | RFC 7541 §B codec. Shared by HPACK (example/http2) and QPACK (example/quic-http3). |
| Logger | `spaznet::Logger` | **Stable** | Optional; no I/O on the hot path unless enabled. |
| **example/http** | `spaznet::http::HTTPHandler` + `make_dispatcher(...)` | **Stable** | Full HTTP/1.1 keep-alive, chunked **request** body, header CR/LF sanitization on responses. `handle_request(const HTTPRequest&, ResponseWriter)` is now a plain synchronous virtual (no `Task`/`co_await`) — answer via `writer.complete(response)`, inline or deferred. See `docs/http.md`. |
| example/http | `spaznet::http::make_reactor_dispatcher(...)` | **Stable** | Coroutine-free counterpart of `make_dispatcher(...)`, registered via `Server::set_connection_factory` instead of `set_connection_handler`. Same `HTTPHandler`/parser/response types, same protocol coverage; `Http1Connection` is an explicit state machine (`ReadingRequest`/`Dispatching`) over `BufferedConnection` rather than a suspended coroutine. Differentially tested against `make_dispatcher(...)` — see `docs/http.md`. |
| example/http | Chunked **trailer** parsing | **Stable** | RFC 9112 §7.1.2 trailer-field lines between the last-chunk and the final CRLF are consumed and dropped (we don't expose trailers on `HTTPRequest`). |
| example/http | Chunk-extension line length | **Limited** | 4 KiB cap; well above real-world integrity-tag extensions but still bounds the per-line scan. |
| **example/http-websocket** | `spaznet::websocket::Handler` + `make_dispatcher(http_handler, ws_handler)` | **Stable** | RFC 6455 compliant. Combined dispatcher: sniffs each connection for a WS upgrade and routes to the WS frame loop, otherwise hands off to example/http. Both `handle_message` overloads (`const&` and `&&`) supported. See `docs/websocket.md`. |
| example/http-websocket | `spaznet::websocket::reactor::Handler` + `make_reactor_dispatcher(...)` | **Stable** | Coroutine-free counterpart, registered via `Server::set_connection_factory` instead of `set_connection_handler`. Unlike the other protocols' reactor counterparts, this one has its own `Handler`/`Connection` interface (`reactor_handler.hpp`) rather than reusing the coroutine one — `Connection::send()` writes straight into the target's `OutputBuffer` instead of `co_await`ing a socket write. Same handshake/framing (`handshake.hpp`, `handler.cpp`'s `Frame`, both shared with the coroutine dispatcher), same protocol coverage; `WsConnection` is an explicit state machine (`Sniffing`/`ReadingHeader`/`ReadingPayload`) over `BufferedConnection`, falling through to `http::attach_reactor_dispatcher` for non-upgrade connections. Differentially tested against `make_dispatcher(...)` — see `docs/websocket.md`. |
| example/http-websocket | `spaznet::websocket::send_message` | **Stable** | Free function (was `Socket::send_websocket_message`). One-allocation frame builder. |
| example/http-websocket | WSS (`listen_tls` + ALPN `http/1.1`) | **Stable** | Same core TLS path as HTTPS; upgrade sniff runs after handshake. Demos `--tls`; integration test for both dispatchers. |
| **example/http2** | `spaznet::http2::Handler` + `make_dispatcher(...)` | **Stable** | h2c (RFC 9113 §3.4, prior-knowledge cleartext). Connection preface, SETTINGS exchange, HEADERS+DATA dispatch through HPACK with Huffman decode (via `spaznet::codec`), per-stream flow control, WINDOW_UPDATE / PING / GOAWAY / RST_STREAM. Verified against `curl --http2-prior-knowledge`. `handle_request(const Request&, ResponseWriter)` is a plain synchronous virtual (no `Task`/`co_await`/`Socket&`) — answer via `writer.complete(response)`, inline or deferred. See `docs/http.md`. |
| example/http2 | `spaznet::http2::make_reactor_dispatcher(...)` | **Stable** | Coroutine-free counterpart of `make_dispatcher(...)`, registered via `Server::set_connection_factory` instead of `set_connection_handler`. Same `Handler`/`codec.cpp` (HPACK, frame parsing/building), same protocol coverage; `Http2Connection` is an explicit state machine (`Preface`/`FrameHeader`/`FramePayload`) over `BufferedConnection` rather than a per-connection coroutine plus a detached per-stream one. Every `ResponseWriter` completion — the case where multiple can be genuinely outstanding at once, unlike HTTP/1.1's, UDP's, or WebSocket's reactor dispatchers — routes through `IOContext::post_to_io_thread()`, so all connection-state mutation provably happens on one thread; no per-connection lock (see `docs/concurrency-and-coroutines.md`'s "Reactor Threading Model"). Differentially tested against `make_dispatcher(...)` — see `docs/http.md`. |
| example/http2 | h2 over TLS (the `h2` ALPN) | **Stable** | Via core `Server::listen_tls` with `alpn={"h2"}`. Differentially tested (curl `--http2`) for both dispatchers. |
| example/http2 | HPACK dynamic table | **Not implemented (intentional)** | Advertises `SETTINGS_HEADER_TABLE_SIZE=0` to peers; encode emits literal-without-Huffman. |
| example/http2 | PUSH_PROMISE / server push | **Not implemented** | Disabled via SETTINGS. |
| example/http2 | Trailers, priority frames | **Not implemented** | Priority frames are silently dropped per RFC 9113 §4.1. |
| example/http2 | Multiplexing | **Stable** | Both dispatchers dispatch each fully-arrived request without blocking on any other stream: the coroutine dispatcher via a detached coroutine per stream via `IOContext::schedule`, the reactor dispatcher via a synchronous `handle_request()` call straight from the frame-reading loop that returns immediately whether the handler answers inline or defers. All wire writes funnel through a single per-connection writer (a writer coroutine + queue for the coroutine dispatcher, `BufferedConnection::write()` directly for the reactor one) for per-frame atomicity, but frames across streams are free to interleave. Test: `HTTP2MultiplexingTest.FrameLoopUnblockedBySlowHandler`, parameterized over both dispatchers, proves the frame loop emits PING-ACK while a handler is mid-defer. |
| **example/udp** | `spaznet::udp::Handler` + `make_dispatcher(...)` | **Stable** | Handler-interface idiom over `set_datagram_handler`. `handle_packet(const Packet&)` is a plain synchronous virtual (no `Task`/`co_await`) — `Packet` carries raw sockaddr + listen fd so handlers can `sendto()` directly. |
| example/udp | `spaznet::udp::make_reactor_dispatcher(...)` | **Stable** | Coroutine-free counterpart of `make_dispatcher(...)`, registered via `Server::set_sync_datagram_handler` instead of `set_datagram_handler`. Same `Handler` interface either way — since `handle_packet` is already synchronous, this adapter just calls it directly with no coroutine involved at all. |
| **example/quic-http3** | `spaznet::quic::TlsContext`, `quic::Connection`, `quic::Listener` | **Experimental — server-only, partial** | Handshake + 1-RTT data work; interops with our own client. See `docs/quic-http3.md` and `docs/quic-security.md` for what's in and what's out. |
| example/quic-http3 | `QuicHttp3CurlInterop` integration test | **Stable** | Spins the server up on a real loopback UDP port and runs `curl --http3-only` against it. GTEST_SKIPs cleanly when the host curl lacks HTTP/3 (macOS system curl, stock Ubuntu curl). Honors `SSLKEYLOGFILE` for Wireshark debugging. To actively run the wire-level test, install an HTTP/3-capable curl (e.g. build from source against `nghttp3` + `ngtcp2`, both packaged on Ubuntu 24.04 as `libnghttp3-dev` / `libngtcp2-dev`). |
| example/quic-http3 | QUIC client mode | **Not implemented** | `Connection::Role::Server` is the only enumerator. |
| example/quic-http3 | Key update (RFC 9001 §6) | **Stable** | 1-RTT KEY_PHASE bit is honored on the wire. `install_new_keys` stashes the Application traffic secrets and pre-derives "phase + 1" packet keys via the `quic ku` label, so an inbound short-header packet with the flipped KEY_PHASE decrypts in one pass; on success the recv side ratchets and (per §6.1) the send side ratchets in lockstep. `Connection::initiate_key_update()` exposes the server-initiated path: rotates send keys, leaves recv waiting for the peer's response. Header-protection keys are intentionally not rotated. Tests: `QuicConnection.AcceptsPeerInitiatedKeyUpdate`, `QuicConnection.ServerInitiatedKeyUpdate`. |
| example/quic-http3 | Connection migration / path validation | **Limited** | `Listener` freezes the per-connection routing address once `Connection::handshake_complete()` returns true. A forged short-header datagram from a spoofed source no longer redirects our response traffic. Inbound `PATH_CHALLENGE` is echoed as `PATH_RESPONSE` on the existing path. We do not validate or migrate to alternate paths ourselves — legitimate NAT rebinding post-handshake will break the connection. Tests: `QuicConnection.RespondsToPathChallenge`, `QuicListener.FreezesPathPostHandshake`. |
| example/quic-http3 | PTO retransmission (RFC 9002 §6.1+§6.2) | **Stable** | `Connection::on_timer` calls `check_pto()`; ACK processing samples RTT and runs the packet-threshold + time-threshold loss-detection rules. Dropped packets are re-queued via `Stream::on_lost` / `crypto_pending_` and re-emitted by the next `build_and_send`. Test: `QuicConnection.PtoRetransmitsDroppedStream`. |
| example/quic-http3 | Flow control + stream limits (RFC 9000 §4.1 / §4.6) | **Stable** | Connection-level receive flow control: aggregate received bytes are charged against our advertised `initial_max_data`; an overrun (or a per-stream / final-size violation) triggers `FLOW_CONTROL_ERROR`. As the application consumes bytes the window is extended and a `MAX_DATA` frame is emitted. Send side honors the peer's connection `MAX_DATA` (from transport params + inbound `MAX_DATA`) across all streams. `MAX_STREAMS` is enforced on peer-initiated streams (`STREAM_LIMIT_ERROR`) and credited as streams fully close (bounding concurrent streams while retiring closed ones to cap memory). Inbound `MAX_STREAM_DATA` / `RESET_STREAM` / `DATA_BLOCKED` / `STREAMS_BLOCKED` are processed. Tests: `QuicConnection.RejectsStreamBeyondMaxStreams`, `QuicConnection.EnforcesConnectionMaxData`, `QuicConnection.EmitsMaxDataAfterConsume`, `QuicStream.SendRespectsConnectionLevelFreshBudget`. |
| example/quic-http3 | Idle timeout enforcement | **Stable** | RFC 9000 §10.1: `Connection::on_timer` checks `now - last_activity_` against the lesser of our and the peer's `max_idle_timeout_ms` and flips state to Draining silently (no CONNECTION_CLOSE on the wire). Test: `QuicConnection.IdleTimeoutFlipsToDraining`. |
| example/quic-http3 | CONNECTION_CLOSE emission | **Stable** | Triggered automatically on frame-parse failure (RFC 9000 §11.1, FRAME_ENCODING_ERROR), and exposed as a public `Connection::close_with_error(code, application, reason)` for application-level shutdown. Emitted at the best-keyed level (Application > Handshake > Initial); state flips to Closing and further sends are no-ops. Test: `QuicConnection.InitiateCloseEmitsConnectionCloseFrame`. |
| example/quic-http3 | Anti-amplification (RFC 9000 §8.1.2) | **Stable** | Enforced in `Connection::build_and_send`. Validation flips automatically on first decrypted Handshake packet, or via `mark_peer_address_validated()`. |
| example/quic-http3 | Retry token validation | **Stable** | Enabled by `Listener::Config::require_retry`. Token is peer-address-bound (HMAC-SHA256-trunc-128). See `docs/quic-security.md`. |
| example/quic-http3 | 0-RTT / session resumption | **Not implemented** | Deferred. |
| example/quic-http3 | `http3::QuicHttp3Service`, `http3::Http3Server` | **Experimental** | Static-table QPACK only (server advertises `SETTINGS_QPACK_MAX_TABLE_CAPACITY=0`). HEADERS + DATA frames work end-to-end. Server push not implemented. |
| example/quic-http3 | `http3::make_reactor_dispatcher(...)` | **Stable** | Coroutine-free counterpart of `make_dispatcher(...)`, registered via `Server::set_sync_datagram_handler` instead of `set_datagram_handler`. `make_dispatcher`'s `Task` never actually suspends — the QUIC/HTTP3 transport underneath is already a synchronous pump — so this adapter is a mechanical swap, calling the same `QuicHttp3Service::handle_datagram` directly with no coroutine involved at all. |

## Reading the status column

- **Stable**: under test, documented, no known design-level bugs. Safe to depend on. Source-level breakage is reserved for security or correctness fixes and is called out in `CHANGELOG.md`.
- **Experimental**: works for the cases the tests cover, but the API surface or wire-level behavior may shift. Pin a SHA and re-test on bumps.
- **Limited**: the feature works for common cases but has an explicit cap (size, count, scope) that real-world peers can exceed.
- **Stub**: the type exists; the method body is a no-op.
- **Not implemented**: the feature isn't here. Calling for it will fail at compile time or at runtime depending on the surface.
- **Not implemented (intentional)**: the feature is deliberately not provided, and the absence is part of the design — e.g. HPACK dynamic table is off because we advertise `HEADER_TABLE_SIZE=0` to peers.
- **Disabled**: code exists and is in tree, but the build excludes it. Re-enabling requires a CMake flag and accepting known defects.
